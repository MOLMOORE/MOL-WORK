## 1. 滚轮翻页开关
- 需求：给用户一个能关掉「滚轮翻页」的按键，某些情况下防误触。
- 根因：无（新功能）。原先普通滚轮在页面滚到顶 / 底之后就代替用户翻页（攒够 140 的 deltaY 走一步）。
- 改法：新增 wheelFlip 状态，存 localStorage 键 workstation.reader.wheelflip.v1，默认开（保持原行为）；
  滚轮回调在 Ctrl 判据之后加一句「wheelFlip 为假就直接 return」，Ctrl+滚轮缩放与「连续」布局不受影响；
  工具条「翻页动效」右边加 ToggleChip「滚轮翻页」，只在书页模式且非连续布局时出现，切换时走舞台就地提示 showHint。
- 位置：`ReaderPage.tsx`（WHEEL_FLIP_KEY / wheelFlip / 滚轮 onWheel / 工具条 ToggleChip）。
- 验证：L0。

## 2. 对比「上移一层 / 下移一层」点了没反应
- 根因（两条叠加，本轮才挖全）：
  1. **层级编号撞车**：compareSlots 给第 i 页 z = count - i，但挑页是「一页一页加进来」的，
     合并时只有新页取格子、老页保留自己那份 —— 加第 2 页时两页都是 z=1，加第 3 页时第 3 页又与第 1 页撞成 1。
     shiftZ 是「交换两页的 z」，交换两个一样的数字就是空操作，界面一丁点变化都没有。
     （第 4 轮修的「方向写反」是真 bug，但撞号这条一直留着，所以用户连着三轮都说「无效」。）
  2. **一点就置顶**：startDrag 无条件 raise(page)，而放大后左键按住纸面走的正是 startDrag，
     于是刚点「下移一层」，随手按住纸面想看一眼 —— 这一页又被提到最上层，看着就是调不动。
- 改法：
  1. 新增 normalizeZ(map, pages)：按现有 z 升序（同值再按页码）重排成一串互不相同的 1..n，相对次序不变；
     新增 zCollides 判撞号；挑页合并的 effect 改成「页集合齐全且无撞号才 return prev」，relayout / stack 之后也走一遍。
  2. startDrag 只在真要搬整张纸时（mode 为 move，或中键）才 raise；左键按住纸面平移不动层级。
  3. 可见性：新增 stackOrder（按 z 降序）+ layerNo(page) 统一算「第几层」，角标显示 n / 总数；
     到顶 / 到底时按钮 disabled 并把 title 改成「已经在最上面 / 最下面」，CSS 补 .cmp-ico:disabled（淡色 + 取消 hover）；
     新增顶部「叠放」按键 stack()：把几页按同一尺寸错开 30/26px 摞成一叠 —— 两页并排不重叠时，上下层怎么调都不可能看出来，这是「无效」的另一半。
- 位置：`ReaderPage.tsx`（cmpKey / zCollides / normalizeZ / stackOrder / layerNo / stack / raise / shiftZ / startDrag）、`index.css`（.cmp-ico:disabled）。
- 验证：Playwright 最小 DOM 复现（work/patch/cmpdom.html + cmpdom.mjs）—— 两张卡 z 都是 1 时，换 z 是空操作（复现用户现象）；把 A 的 z 改成 2，elementFromPoint 立刻从 cardB 变 cardA。

## 3. 放大后左键拖不动右下、中键同一片也失灵（滚动条却正常）
- 根因：**起拖判据用错字段**。第 4 轮为了「别抢纸框自己的滚动条」写了
  「mode 为 pan 时，若 nativeEvent.offsetX 大于 currentTarget.clientWidth 就不起拖」。
  但按规范 offsetX/offsetY 是相对**被命中的那个元素**（这里是纸面）的填充边算的，
  放大后纸面远比纸框宽，指针一往右下走 offsetX 立刻超过 clientWidth → 整片被误判成滚动条直接 return，
  既不左键平移也不中键拖整页；而原生滚动条不经过这段代码，所以「进度条一直可以拖」。
- 改法：改成按纸框自己的矩形量：取 getBoundingClientRect，用 clientX - box.left 与 frame.clientWidth 比。
- 实测证据（纸框 320x220、放大 6 倍、滚到最右下）：纸面中点 offsetX=875 / offsetY=1218，而 clientW/H=320/220
  → 旧判据 true（错误当成滚动条），新判据 false（正常起拖）。
- 位置：`ReaderPage.tsx` startDrag。
- 参考：MDN MouseEvent.offsetX ——「相对触发事件元素的填充边」；同样的坑在 pointer 事件上一样。

## 4. 「拖到最右下还是差一截看不全」
- 根因：可滚上限按公式「内容尺寸 - 纸框尺寸」推，漏掉纸框那圈 padding:8px（Blink 对滚动容器末端 padding 算不算进可滚范围历来有差异，crbug 748518）。
- 改法：**以 DOM 量为唯一权威** —— 每帧布局后测 scrollWidth - clientWidth / scrollHeight - clientHeight，
  按 cmpKey（框宽 x 框高 @ 倍率）缓存在 scrollMax；clampScroll 在框与倍率没变时直接用缓存的真值（拖动过程中恒成立），
  刚改过倍率 / 框幅的那一帧才退回公式，渲染完再被 DOM 纠正；越界的期望值顺手写回状态，免得下次起拖先空拖一段。
- 实测证据：内容 1027x1320、纸框 320x220 时，公式上限 706/1100 → 纸面右下角仍藏 8px；DOM 真上限 723/1116 → 纸面完整可见（外圈还剩 8px 内边距）。
- 顺带：放大锚点的换算补上这圈内边距 —— 新增 CMP_FRAME_PAD（与 .cmp-frame 的 padding 一一对应，CSS 里也留了互相指认的注释），原来是 (scroll + p) * times - p，现在是 (scroll + p - PAD) * times + PAD - p，滚轮连放大时指针那一点不再逐档漂移。
- 位置：`ReaderPage.tsx`（scrollMax / cmpKey / clampScroll / CMP_FRAME_PAD / setCardZoom / 写回滚动位置的 useLayoutEffect）。
