# v1.2.7 第十一轮 · 转换工具：拖入文件按文档名成列显示

> 功能线：`docs/modifications/by-feature/tools-convert.md`

## 需求
- 工具页转换类工具（图片 / 音频 / 视频 / 文档）：文件拖进来后要能一列一列看到文档名，批量转换的显示也依托这一列。

## 根因
- 第十轮的「批量转换队列」卡在参数表单**下方**，拖入后视线还在表单上，列表在折叠区外；
- 且单个文件只填源文件输入框、不进队列，拖一个 / 拖一批的显示完全不同，批量转换的存在感很弱。

## 改法
1. 左栏表单上方新增「转换文件」卡：
   - 顶部虚线拖放条 —— 拖入悬停高亮（复用外层 `dragIn`），点一下走 `app:pick-files` 多选；
   - 下面一行一个文件：序号、文档名（`fileNameOf`，`title` 为全路径）、所在目录（`dirNameOf`）、状态徽章（排队中 / 转换中 / 成功 / 失败）、失败原因首行、产物文档名；
   - 底部 `Progress` + 「正在转换第 k / n 个」+「开始批量转换」；表头汇总「共 N 个 · 成功 x · 失败 y」。
2. 行为：
   - 单个文件也进这一列；队列为空或源文件未填时，第一个文件自动填进源文件框，「执行工具」照常单张转换；
   - 点文件行 = 设为当前源文件（该行高亮 + `源文件` 徽章）；行尾 `X` 移出，若移出的正是源文件则回填下一行；
   - 「执行工具」跑完后把同一文件那行状态同步为本次结果；
   - 「重置」只清参数、保留队列并回填源文件；卡内「清空」把队列与源文件一起清空；
   - 无扩展名的拖入项按文件夹处理：toast「已忽略 N 个文件夹」，不再静默进队列后报看不懂的错。
3. 旧的「批量转换队列」卡删除；`BatchRow` / `BATCH_STATE_LABELS` / `BATCH_STATE_TONES` / `fileNameOf` / `dirNameOf` 提到模块级；`batchField` 声明上移到 `handleRun` 之前。

## 位置
- `src/renderer/src/pages/ToolRunPage.tsx`：`BatchRow`、`BATCH_STATE_LABELS/TONES`、`fileNameOf/dirNameOf`、`addBatchFiles`、`removeBatchFile`、`handleFormDrop`、`sourceField`/`okCount`/`failCount`/`todoCount`/`runningIndex`、「转换文件」卡 JSX
- `src/renderer/src/components/ui/Feedback.tsx`：`Progress`（只读复用，未改动）
- `src/renderer/src/components/tool/ToolRunnerForm.tsx`：源文件旁多选键不变（同一 `addBatchFiles`）

## 验证
- L0：改动回读复核；`npx tsc --noEmit -p tsconfig.web.json` 0 错；`npm run build` 三端通过。
- L1：`npm run dist` 打包 + asar 回读「转换文件」卡文案与新增符号、CSS 类在产物内。
- 端到端拖拽目检留给用户（按第 4 节默认档位，不跑 selftest）。

## 风险 / 遗留
- 批量运行中不接受新拖入（与第十轮一致）；中途改参数只影响未跑项。
- 「无扩展名 = 文件夹」是启发式：无扩展名的真实文件会被忽略并提示（转换工具本身要求扩展名，影响可接受）。
- 队列只存路径，重启后不保留（与表单状态同生命周期）。
