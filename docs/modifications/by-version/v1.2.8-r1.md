# v1.2.8 第一轮 · 应用内自动更新

## 需求
- 启动后自动检查 GitHub 最新版。
- 用户在设置页一键下载更新，下载完成后可重启安装。
- 不实现 GitHub 登录、私人仓库和云端备份。

## 根因
- 设置页原先仅显示“本地应用无在线更新源”。
- 项目未安装 `electron-updater`，未配置 GitHub publish，Release 流程也未上传自动更新必需的 `latest.yml`。

## 改法
- 新增主进程更新服务，集中管理检查、下载、安装和错误状态。
- 新增更新状态事件与五个 IPC 动作；preload 只转发类型化接口。
- 设置页“关于与版本”接入状态、版本号、下载进度、失败原因和操作按钮。
- 关闭 `autoDownload` 与 `autoInstallOnAppQuit`，避免后台偷偷下载或退出时意外安装。
- 自动检查只在正式安装包中启用；开发、自检和绿色版解包模式显示不可用原因。
- 发版配置加入 GitHub provider，后续 Release 必须同时上传 exe、blockmap 与 `latest.yml`。
- 默认 GitHub provider 访问 `github.com/releases.atom` 时遇到 `ERR_CONNECTION_RESET`；新增自定义 provider，改走可访问的 `api.github.com` 查询 Release、读取 `latest.yml` 并获取安装资产。
- 自定义 provider 使用完整安装包下载并关闭差分下载，保留下载完成后的 SHA-512 校验与 NSIS 安装流程。

## 验证
- node / web TypeScript 检查均为 0 错。
- `npm run build` 三端通过。
- `npm run dist` 成功，产物内 `app-update.yml` 指向 `MOLMOORE/MOL-WORK`，`latest.yml` 版本为 1.2.8。
- `app.asar` 回读确认更新服务、GitHub Release 地址、自动更新 UI 与“重启并安装”按钮均进入安装包。
- provider 隔离烟测确认请求走 `api.github.com`；当前 Latest `v1.2.7` 缺 `latest.yml` 时返回“缺少 latest.yml”，不再连接 `releases.atom`。
- 文档治理：全部 Markdown 统一为 UTF-8 无 BOM、CRLF；`npm run check-docs` 为 0 错误、0 警告。

- 真正的下载与重启安装需要 v1.2.8 发布后，用下一版本 Release 做一次端到端复验。
