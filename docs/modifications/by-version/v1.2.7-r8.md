# v1.2.7 第 8 轮 · 修复自绘标题栏遮挡浮层（2026-10-14）

## 需求
- 用户报告：顶部栏会挡住右侧「任务日程」详情抽屉的显示（抽屉标题行被盖住一半），并要求排查其他遮挡。

## 根因
- 自绘标题栏 `.app-titlebar` 在根层 z-index:60（styles/index.css），而任务详情抽屉、各页 Modal/ConfirmDialog 都是 `fixed inset-0 z-50`（ui/Overlay.tsx），且嵌在 AppLayout `.relative z-10` 或 Routes 容器内 —— 有效层级翻不过 z-60，浮层顶部 32px（h-8 标题栏，bg-surface 不透明）被盖：抽屉只剩副标题「项目 · 更新于…」可见，标题行与关闭键上半截消失。
- 反向遮挡一处：阅读界面对比工作台 `z-[70]`（ReaderPage）原先**盖住**标题栏，对比模式开着时窗口最小化/最大化/关闭全部点不到。

## 改法
- 全局一次修好，不逐个改浮层：给 `App.tsx` 中包裹 `<Routes>` 的容器加 `transform-gpu`（translate3d(0,0,0)）。带 transform 的祖先成为所有 fixed 后代的包含块 → 全站浮层统一以「标题栏以下」为视口锚定，遮罩、抽屉、弹窗、对比台一并归位；全屏（F11）时标题栏不渲染、该层即整窗，浮层仍铺满，无死带。
- `<CloseBehaviorDialog />` 从根 div 末尾挪进该容器内（它原先在锚定层外，关闭确认弹窗顶部同样会被标题栏切到）。
- 排查结论（其余 fixed 浮层）：Toaster（右下）、笔记页底部拖放提示（bottom-center）、GlobalSearch / 铃铛 / 状态菜单下拉（TopBar 内 absolute）均不与标题栏交叠，无需改动。

## 位置
- `src/renderer/src/App.tsx`（浮层锚定层 + CloseBehaviorDialog 归位）；机制记录追加在 `by-feature/window-chrome.md` 篇首。

## 验证
- L0：web tsc 0 错 + `npm run build`；产出 CSS 回读确认 `.transform-gpu` 规则存在（translate3d 非 none，包含块生效）。
- 层级推演：锚定层 z-auto，其内浮层无论 z-50/z-70 都被封在该上下文 → 标题栏（z-60）恒可见可点；TopBar z-40 与浮层同上下文，抽屉仍盖顶栏（原有正确行为不变）。
- 未跑 selftest（档位不需要）；待用户装包目检抽屉/弹窗/对比三处。

## 遗留 / 风险
- transform 使整个应用内容合成一层 GPU layer，Electron 内开销可忽略；若日后有浮层**故意**要盖标题栏（如系统级全屏浮窗），需挂到锚定层外并显式提层。
- 本轮并入 v1.2.7（未发布）；合并推送与 Release 仍待用户手动验收。
