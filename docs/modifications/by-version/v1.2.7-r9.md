# v1.2.7 第 9 轮 · 文档转换加 doc ↔ PDF 互转（2026-10-16）

## 需求
- 给工具集的「文档转换」加 doc 与 PDF 的互相转换；用户明确要求先找成熟开源项目参考，不自己写实现。

## 参考（先查后抄）
- doc/odt/rtf/html/txt → PDF：LibreOffice 无头 `soffice --headless --convert-to pdf --outdir <dir> <file>`（unoconv / libreoffice-convert 通用做法）；Windows 坑：已有 GUI 实例时命令会被转交并立即返回 → 带独立 `-env:UserInstallation` 配置目录（libreoffice-convert 同款）；winget id `TheDocumentFoundation.LibreOffice`，默认装 `C:\Program Files\LibreOffice\program\soffice.exe`（不写 PATH，需目录探测）。
- PDF → Word：开源 `pdf2docx`（pypi，版面/表格/图片重建，需 Python 3.10+），自带控制台入口 `pdf2docx in.pdf out.docx`，pip Scripts / PATH / winget Links 均已在既有二进制探测路径内。
- pandoc 不能读 PDF、默认也产不了 PDF（要 LaTeX）：md/tex/epub → PDF 走「pandoc→docx 中间件 + LibreOffice 排版」两级链。

## 改法
- `doc-convert.runner.ts` 重写为四路引擎路由：① pdf 源 → 仅 .docx（pdf2docx），其余目标给引导文案；② pdf 目标 → SOFFICE_OPENS 集合直接无头转换，否则 pandoc 出暂存 docx 再链 soffice；③ .doc 源非 pdf 目标 → soffice 归一化 docx 后交 pandoc（.doc→.docx 单步直转）；④ 其余格式对 → pandoc 原路径不变。产物先落 `workspace-tmp/doc-convert` 暂存再 moveInto 到最终唯一路径（跨盘 EXDEV 回退复制+删除）；soffice 超时 5 分钟。
- 新依赖 `soffice` / `pdf2docx` 全链路接线：`domain.ts#DependencyId`、`constants.ts#DEPENDENCY_META`（安装指引）、`binaries.ts#ToolBinaryId + probeLibreOffice`（Program Files / (x86) / LOCALAPPDATA\Programs / macOS /usr/lib 等目录 + PATH 的 libreoffice 别名）、`dependency-check.ts#PROBE_ARGS`（soffice --version / pdf2docx -h）与 `checkDependencies` 列表、`scripts/check-tools.mjs` 镜像探测同步。
- `convert-shared.ts`：DOC_EXTS 加 .pdf/.doc；ExternalRun.engine 加 pdf2docx；manifest 目标格式加 PDF、描述与 hint 更新、requires 三项。

## 位置
- `src/main/tools/runners/doc-convert.runner.ts`、`convert-shared.ts`、`src/main/utils/{binaries,dependency-check}.ts`、`src/shared/{types/domain,constants}.ts`、`scripts/check-tools.mjs`。

## 遗留 / 风险
- soffice 首次运行要初始化独立 profile，第一次转换会慢几秒；profile 常驻 `workspace-tmp/doc-convert/lo-profile`。
- pdf2docx 对扫描件（纯图片 PDF）只能出图片版 docx，非 OCR 范围；soffice 对复杂 Word 版式（艺术字、域代码）还原度取决于 LibreOffice 本身。
