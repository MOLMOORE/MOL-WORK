# v1.2.8 发布（2026-11-11）— GitHub API 自动更新

## 需求
- 启动后自动检查 GitHub Releases，用户可一键下载，下载完成后重启安装。
- 当前网络无法访问 `github.com/releases.atom`，必须绕过连接重置。

## 根因
- electron-updater 默认 GitHub provider 从 `github.com/.../releases.atom` 查询版本，当前网络对该路径返回 `ERR_CONNECTION_RESET`。
- `api.github.com` 可正常访问，Release Asset API 也能通过重定向下载资产。
- 旧 Latest `v1.2.7` 没有 `latest.yml`，即使连接恢复也无法判断更新。

## 改法
- 新增 `GitHubApiUpdateProvider`：通过 `api.github.com` 读取 Latest Release 和 `latest.yml`。
- `resolveFiles()` 将安装文件名映射到 Release Asset API URL，并使用 `application/octet-stream` 下载。
- 关闭差分下载，下载完整安装包；完整性由 `latest.yml` 的 SHA-512 校验。
- Release 同时上传 exe、blockmap 和 `latest.yml`，并设为 Latest。

## 位置
- `src/main/services/github-api-update.provider.ts`
- `src/main/services/update.service.ts`
- `src/renderer/src/pages/SettingsPage.tsx#AboutSection`
- `electron-builder.yml#publish`

## 验证
- 真实 API provider 烟测通过：Latest 为 `v1.2.8`，安装资产映射到 API Asset URL。
- 远端资产与本地 SHA-256 逐项一致：
  - exe：102,024,963 B，`aeb1c8fa…2d13d54`
  - blockmap：108,329 B，`f0c485fa…f3753a3`
  - latest.yml：367 B，`fdbf320e…acf05ab`
- 安装包内确认使用 API provider，应用侧不含 `releases.atom`。
- Release：<https://github.com/MOLMOORE/MOL-WORK/releases/tag/v1.2.8>

## 遗留
- 安装包未签名，Windows SmartScreen 仍可能提示未知发布者。
- `v1.2.7` 必须手动安装一次 `v1.2.8`，之后才能使用应用内更新。
- 完整安装包的下载与重启安装要在下一个高于 1.2.8 的版本发布后做端到端复验。
