# v1.2.6 第 3 轮 · 工具集重做 + 配色精简 + 提示文案重写 + 标题栏融合

> 提交：`develop` 上的本轮提交，标签 `v1.2.6` 随本轮移动（v1.2.6 尚未发布，三轮共用一个版本号）。

## 需求
1. 工具界面更简洁紧凑；搜相关开源项目改进，增删工具，必须加入滤波电路的快速运算等工具。
   - 用户补充：**工具尽量用现成的程序 / 开源项目，不要什么都自己写**。
2. 默认主题的「配色风格」只保留前 5 个，其余删除。
3. 重写全应用面向用户的提示：精简明了；不得写入 agent 的思考过程，也不得整段照抄用户的修改要求；每处先判断是否真的需要提示，不需要就不写。
4. 删掉标题栏里多出来的那个软件图标，让软件顶层融合更自然简洁。

## 根因 / 判断依据
- 工具页顶部那张「可插拔工具集」说明卡与顶栏标题完全重复，白占一行；四张指标卡里「今日调用」「累计工具耗时」是同一件事的两半；外部依赖卡用大瓦片把整条路径摊出来，一屏放不下几项 —— 这就是「不紧凑」的来源。
- 计算类工具原来只有单位换算 + 电路十选，缺滤波器设计；`circuit-calc` 的 description 把十条 hint 拼成一句话（典型的把需求当文案写），卡片上三行都装不下。
- 滤波电路的算法要不要自己写：先核验开源实现再决定。
  - `digital-filter`（audiojs，MIT）是**数字**滤波器设计（z 域、需要采样率），与「RC/LC 电路」不同域，不采用；
  - `brownout` / `eecircuit-engine` 体积 4.8 MB / 43 MB 且 ESM+JSON import attributes，打进主进程风险高，暂不采用；
  - ngspice：本机与 winget 均无该包（`winget search ngspice` 无结果），无法在本机验证，不引进；
  - **采用 `analog-filter-designer@1.0.1`（MIT，零依赖，60 KB，CJS 双导出）**：复数导纳 MNA + 理想运放 nullor，作者自述已用 ngspice 与六个解析传递函数对照过。
- 配色风格 10 种里后 5 种（暮沙 / 石墨 / 午夜靛蓝 / 紫棠 / 墨绿夜色）与保留的 5 种在色相上高度重叠，用户要求只留前 5 种。
- 标题栏左端那个 16px 图标与侧栏顶部 36px 品牌图标上下重复，且标题栏自己压了一条 border-b，与下方顶栏之间形成「双层甲板」。

## 改法
### 1. 工具集
- 新增 `src/main/tools/engineering.ts`：工程量解析与格式化。`parseQty` 支持 `10k / 4m7 / 100n / 1u / 2p2 / 1e-9 / 1,000 / -20 / 100mhz`，用「尾数字串 + 10 的幂」拼装再交给 `Number()`，避免 `100 * 1e-9 = 1.0000000000000001e-7` 这类残渣；`fmtQty` 自动挑量级前缀（4 位有效数字）；`E24 / E12 / E6 + nearestSeries / standardText` 给就近标准值。
- 新增 `src/main/tools/mna.ts`：开源引擎之上的薄封装 —— `transfer / sweep`（对数扫频）、`bandMetrics`（按 lowpass / highpass / bandpass / notch 选 -3 dB 判据：带通与陷波的参考取峰值，低通高通取两端；多交点时按形状取端点）、`polesAndZeros`（极点频率与 Q）、`stepResponse`、`toCsv`、`decadeTable`。
- 新增三个 runner：
  - `filter-calc.runner.ts`「滤波电路速算」：rc / lc（常数 k 的 L·T·π 型）/ sallen / twin / resonant / rolloff / reactance / db 八类，设计方向（给 fc 反算 R、C）与标准值建议都在这里；
  - `filter-sim.runner.ts`「滤波电路仿真」：九种电路结构搭网表交给 MNA 解，实测 -3 dB 点、极点零点、通带峰值、阶跃上升时间与过冲，曲线写进 `outputs/` 并作为 resultPath；
  - `opamp-calc.runner.ts`「运放比较器速算」：gain / gbw / slew / hysteresis / noise。
- `ToolField` 新增 `visibleWhen: { key, values }`（`src/shared/types/domain.ts`），`ToolRunnerForm` 新增 `visibleFields()` 只渲染当前模式的输入项，`ToolDetailDrawer` 的必填校验也只看可见字段 —— 多模式计算器不再一次摆出十几个输入框。
- 删除：`flashcard.runner.ts`（与笔记页新建卡片 + 复习引擎重复）、`ToolCategory` 的 `'flashcard'`、`TOOL_CATEGORY_META.flashcard`、`ToolsPage.CATEGORY_ORDER` 里的卡片项；`circuit-calc` 去掉 rc / lc 两个模式（并入滤波速算），字段由 `number` 改 `text` 走 `parseQty`，description 从十条 hint 拼接改成一句话。
- `ToolsPage.tsx`：说明卡 → 一条只有按键的操作条；指标卡 4 → 3（今日调用与累计耗时并成「运行记录」一张，明细弹窗同步三态）；外部依赖卡由四列瓦片压成一行一条（路径与安装指引收进 title 悬停）；工具卡 `p-4 → p-3`、`gap-3 → gap-2.5`、描述三行改两行、分类标签不再大写；看板 `storageKey` 升 `workstation.grid.tools.v5`。
- `npm run selftest` 的阶段三改为跑 `filter-calc / opamp-calc / filter-sim`（原来跑的是已删除的 flashcard-maker）。

### 2. 主题

- **工具端到端**（`work/scratch/fsim-test.mjs`、`calc-test.mjs`，esbuild 直接打包 runner 后跑真实 run()）：
  - 九种电路结构全部跑通；RC 低通实测 159.4 Hz vs 解析 159.155 Hz；带 10 kΩ 负载后 317.9 Hz vs R‖RL 解析 318.31 Hz（加载效应确实进来了）；两级缓冲 RC 102.9 Hz vs 102.43 Hz；Sallen-Key 极点 164.2 Hz / Q 0.69 与解析一致；双 T 陷波 159.2 Hz、深度 -73.6 dB（受扫频分辨率限制）；LC 三节 28.77 kHz vs 影像截止 31.83 kHz（有限节数的正常偏离）。

## 遗留 / 风险
- `analog-filter-designer` 是 2026-07 新发布的个人项目（2 个版本、单一维护者、作者自述代码由 AI 协助编写）。本项目只用它的 `solveAC / poleZeroMap / simulateTransient` 三个函数，且已独立复核；若上游断更，可把 `engine/*.js`（约 20 KB）vendored 进仓库，接口不变。
- 理想运放是 nullor 模型：没有 GBW、压摆率与输出摆幅限制，仿真结果在高频大信号下会偏乐观（要算这些请用「运放比较器速算」）。
- 极点零点靠有理拟合，节数 ≥ 4 或高 Q 时可能不收敛 —— 已 try/catch 降级为「只给扫频结果」。
- 仿真每次执行都写一个 CSV 到 `outputs/`，不做清理；量小，暂不加回收策略。
- 配色风格删除后，若用户之前挑的正是被删的那套，界面会落回基础配色（不会坏），但设置页仍显示「素白简约」，需要他自己再点一次才写回新值。
- 备选开源件记录：`digital-filter`（数字 IIR/FIR 设计，若以后要做「数字滤波器」工具可直接用）、`brownout`（JS 混合信号 SPICE 引擎，4.8 MB）、`eecircuit-engine`（43 MB）、`ioe-rf-calculations`（射频单 / 双调谐回路计算）。
